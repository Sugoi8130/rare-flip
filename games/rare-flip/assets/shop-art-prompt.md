# Shop item atlas v2

Generated with the built-in image generation tool. Style reference: `arcade-room.png`. Output copied into this project as `shop-items-v2.png`. The source is preserved in the generated-images directory. The game crops individual sprites using explicit bounds in `shop-art.tsx`; it does not display this atlas as a concept image.

## Final prompt

Use case: stylized-concept. Asset type: one production game sprite atlas PNG with actual transparent background, square format. Input reference image is STYLE REFERENCE ONLY, not edit target. Create an exact evenly spaced 3 by 3 sprite atlas of nine isolated items matching this purple/gold fantasy arcade room's rich detailed 2D pixel art. Each sprite centered within its own equal square cell, whole object fully visible, ample clear transparent padding at least 18% on every edge of each cell, no touching neighboring sprites. Row1 left to right: lush teal moon fern in carved copper planter; purple glowing arcade/neon totem cabinet with white rabbit-like face on screen; lavish gold treasure chest with violet panels. Row2: elaborate small golden crown with ruby gemstone; violet magician hat with golden star and gold stitched hatband; teal leather adventure backpack with brass buckle and straps. Row3: golden star dust orbit cluster; cyan comet swoosh with a luminous head and trailing pixel particles; violet and gold firework starburst cluster. All objects polished RPG 16-bit/GBA pixel sprites, dark crisp stepped pixel outlines, 4-6 discrete shading levels per material, rim highlights, visible front and slight top plane like reference room props, consistent upper-left light. Rich material textures in copper, wood, cloth, gold, gemstone. NOT simplistic flat geometric icons, NOT vector, NOT smooth 3D. No labels, no text, no UI card frames, no backgrounds, no room, no character. Transparent alpha around every sprite. Precisely aligned equal 3x3 cells so game can crop each ninth of image independently.

## Verification notes

The output did not follow uniform grid row bounds: the first row is taller. Explicit crop rectangles retain the full item silhouettes. No canvas pixel readback is used because the FriendSDK iframe has an opaque sandbox origin. `capture-shop.mjs` checks sprite loading, simulated purchase/equip and mobile overflow, and captures the real running preview. The shop remains a cosmetic interface prototype with 250 sample FLIP and a preview-only loadout; RF conversion and persistent ownership are not implemented here.
